## Design specificity verdict

Generic. The clip is a stock "toy bricks stack up" animation that any site could use unchanged.

- No name, word or meaningful shape appears in 104 frames. The tagline promises infrastructure and the bricks build a heap.
- The film is generated from a Python script and rendered headless, which is the real DevOps point, but that only appears in a project card three sections down (index.html:99-102).
- The 3D bricks and the page's flat CSS bricks never meet; the wall just dims to wallpaper.
- Detector: `impeccable detect --json index.html` gave 1 finding, `flat-type-hierarchy`, a false positive (the stylesheet is imported from src/main.ts, so it measured browser defaults). Against http://localhost:4317/ it gave 8, none about the intro: `border-accent-on-rounded` x4 (project cards), `hero-eyebrow-chip`, `all-caps-body` (the eyebrow), `line-length`, `repeating-stripes-gradient` (studs).
- Overlays: none; the in-page overlay was skipped because its workflow edits project HTML.

## Overall impression

The plumbing is sound and the motion is pleasant, but the intro costs 5.3 s before the headline is readable and tells the visitor nothing. Biggest opportunity: make the bricks build something that means "Alec".

## What's working

## Priority issues

### [P1] The intro spends 5.3 s saying nothing about Alec
- Why: a recruiter gives a cold link a few seconds, and this spends them on an anonymous toy wall.
- Fix: have the bricks build something recognisable (initials, or pipeline stages), and bring the headline in as the last brick lands. Put "generated from a Python script" in the hero.
- Command: /impeccable bolder

### [P1] No payoff, then a second of dead air
- What: the last brick is grey on grey and lands like the other 27. `HOLD = 30` (blender/intro.py) freezes the frame for 1 s, and the copy waits another 0.7 s (`.hero-copy` transition delay).
- Bug: `pick_colors` compares row-local x, but rows are offset when placed, so "never match the brick below" fails; the apex is three stacked grey bricks.
- Fix: cut the hold to about 6-8 frames, give the last brick a bright colour, a longer pause before it and a harder landing, and fix the picker to use placed x.
- Command: /impeccable animate

### [P1] When loading goes wrong, the visitor gets a black screen
- 400 kbps: about 3 s of flat black, Skip dead until the script arrives (~2 s), three stalls, headline at ~11 s.
- Video aborted or 404: `play()` never rejects with `<source>` children in Chrome, so the page waits the full 8 s (released at ~8.16 s, headline ~9.8 s). The comment at src/main.ts:17 is wrong.
- 80 kbps: the timeout runs from `play()`, not navigation; page released at ~18 s, cross-fading from a half-built wall.
- Script fails to load (inferred, not reproduced): `data-intro="play"` is never cleared, so the page stays black and scroll-locked.
- A failed or timed-out intro still sets `intro-seen`.
- Fix: hero.webp as poster/overlay background; CSS-only failsafe that hides `.intro`; listen for source `error`; run the timeout from navigation and only until `playing`.
- Command: /impeccable harden

### [P1] The headline runs into the wall on laptops and phones
- 1440 px: "brick" ends at x=630, wall starts at x=627. 1024 px and 820 px: headline and lede run across the bricks. 390 px: wall cropped on both sides, copy sits on it; eyebrow worst-case contrast 4.60:1.
- Fix: stack the layout below about 1100 px; render a portrait cut for phones (wall above, copy below) served by `media` on `<source>`.
- Command: /impeccable adapt

### [P2] Keyboard and screen-reader users get a broken overlay
- `aria-hidden="true"` wraps the Skip button, so the accessibility tree exposes no button. Tabs 2-8 reach links hidden behind the video; Enter on "Projects" scrolls the hidden page. No Escape. Focus drops to body when the intro ends.
- Fix: drop `aria-hidden`, make the page `inert` while the intro plays, add Escape, move focus deliberately on finish.
- Command: /impeccable harden
