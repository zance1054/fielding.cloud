## Design specificity verdict

Authored at the top of each page, interchangeable below it. The Blender intro, brick titles with the costumed figure, stud-count charts and scrapbook photos could belong to nobody else. The layer that carries the hiring argument (dark page, cards with a coloured top border, centred column, bullet timeline) is anyone's developer portfolio. The rendered craft covers roughly the first 400px of each page and never meets the CSS below it.

Deterministic scan: the CLI reported 7 flat-type-hierarchy findings, all false positives (it read unstyled source HTML). The in-page detector found: footer paragraph about 143 characters per line on every page; border-accent-on-rounded on all 11 cards; tight leading on p.aside and the Lobbi heading span; possible 16px overflow on p.sign. No contrast failures, no horizontal overflow, no heading skips, no console errors. Target-size misses: button.replay (40px tall), Projects tag links (41.6px), Hobbies card title links (25.8px).

## What's working

1. The intro is engineered: video and hero still share geometry, and the tall cut is a real second render.
2. "Built so far" stat bricks: the one place brick identity and content fuse, each a deep link.
3. Charts that count honestly, one stud per unit, with candid captions.
